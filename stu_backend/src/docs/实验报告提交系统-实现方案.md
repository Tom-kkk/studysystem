# 实验报告提交系统 — 系统实现方案

本文档依据桌面目录 `config.properties` 的配置约定、飞书导出教程目录 `feishu_md` 中的功能与数据库设计，并结合当前工程 `stu_backend`（Spring Boot）技术栈，给出**分阶段实现步骤**。若需与《毕业论文开题报告》严格逐条对齐，请将开题报告中的「研究内容 / 技术路线 / 进度安排」章节要点补充到文末「与开题报告的对应关系」一节（本仓库中的 `.doc` 为二进制格式，无法在此自动抽取正文）。

## 一、业务与范围（与 feishu_md 一致）

- **系统名称**：实验报告提交系统（独立系统，不与其他教务系统对接）。
- **核心规则**：
  - 每门实验课含多个实验项目；学生按项目提交 **PDF**，单文件不超过 **8MB**。
  - 存储文件名统一为：`学号-姓名-实验项目名.pdf`（与用户上传时原始文件名无关）。
  - 目录结构：每门课单独文件夹；同一项目报告进入以**项目名称**命名的子文件夹。
  - 教师通过 **Excel 模板**导入「实验课信息」（课程、项目、学生花名册）；教师可**开放/关闭/截止**某项目的上传。
- **角色**：DBA（运维）、教师、学生。

## 二、配置设计（对照 `config.properties`）

原教程使用 **JNDI 数据源** + **classpath 下 properties**。在 Spring Boot 中建议做如下映射，保持语义一致：

| `config.properties` 项 | 含义 | Spring Boot 建议 |
|------------------------|------|------------------|
| `data_source` | JNDI 名，如 `java:comp/env/jdbc/...` | 使用 `spring.datasource.*`（或 Hikari 直连）；若必须 JNDI，则 `spring.datasource.jndi-name` |
| `hikariCP_config` | 独立 Hikari 属性文件路径 | 合并进 `application.yml` 的 `spring.datasource.hikari.*` |
| `Win_path` / `Linux_path` | 报告文件根目录 | `app.storage.root` + 启动时按 `os.name` 或 `spring.profiles` 选择 |
| `logger_file` | 日志子目录名 | `logging.file.path` 或 Logback `logging.*` + 自定义 appender |
| `from` / `auth_code`（或 `password`）/ `smtpHost` | 发件邮箱与 SMTP | `spring.mail.*` |

**实施要点**：生产环境将敏感信息放在环境变量或独立 `application-prod.yml`，勿提交仓库。

## 三、数据层（对照 `feishu_md/6 数据库设计.md`）

1. **库与表**  
   - Schema：`report`（MySQL 脚本与教程一致）。  
   - 核心表：`tb_User`、`tb_Course`、`tb_SC`、`tb_Project`；教学班明细由 Excel 导入生成的**动态表**参与存储过程 `add_data` / `delete_data`。

2. **Spring Boot 侧**  
   - 使用 Flyway 或 Liquibase 管理 `report.sql` 版本化迁移（推荐），或在文档化流程中「首次手工执行脚本」。  
   - 存储过程调用：通过 `JdbcTemplate` 或 MyBatis `@Options`/`CallableStatement` 调用 `add_data`、`delete_data`。

3. **与教程差异说明**  
   - 原项目为 **Servlet + JSP + JDBC**；本后端为 **REST API**，表结构与业务规则保持一致即可。

| 教程章节（feishu_md） | 功能摘要 | 后端/API 建议 |

| EL/JSTL 重写界面 | 前端展示 | 独立前端（Vue/React）或 Thymeleaf（若坚持服务端渲染） |

## 五、分阶段实现步骤（推荐顺序）

### 阶段 0：工程与规范

1. 固定 JDK（当前 `pom.xml` 为 Java 17）与编码 **UTF-8**。  
2. 在 `src/docs` 维护接口约定（路径、DTO、错误码）。  
3. 划分包结构：`config`、`domain`、`repository`、`service`、`web`、`security`（可选）。

### 阶段 1：基础设施

1. 引入 **Spring Data JDBC / MyBatis / JPA** 之一访问 `tb_*`（择一，与团队习惯一致）。  
2. 配置数据源与连接池（对齐原 Hikari 意图）。  
3. 实现「读取存储根路径」：`Win_path`/`Linux_path` 映射为可配置项，上传前创建目录。  
4. 接入日志（对齐 `logger_file` 子目录语义）。

### 阶段 2：认证与用户

1. 实现登录（用户名即学号/工号，密码规则与教程一致：存储 **MD5** 等，注意与现有 `tb_User` 数据兼容）。  
2. 验证码（对齐 `CheckcodeUtil`）：独立接口输出图片，登录时校验。  
3. 首次登录补全邮箱/改密（对齐 `set_password_email` 流程）。  
4. 邮件：配置 `spring.mail`，实现验证码或通知（对齐 `EmailUtil` + `config.properties` 邮件项）。

### 阶段 3：教师端 — 课程与项目

1. **新建课程**：上传 Excel → 校验列（SNO、Sname、各项目列）→ 动态建表或按教程已有表结构导入 → 调用 `add_data`。  
2. **课程列表 / 项目列表**：`CourseDAO`、`ProjectDAO` 能力 API 化。  
3. **项目开关**：更新 `tb_Project.project_open`（及教程中的截止逻辑，若有扩展字段再增加）。

### 阶段 4：学生端 — 上传与查看

1. 上传前校验：已登录、角色为学生、项目已开放、`listall` 等价列表包含该项目。  
2. 仅允许 **PDF**，大小 ≤ 8MB；保存名为 `学号-姓名-项目名.pdf`。  
3. 路径：`{root}/{course或course_id}/{projectName}/文件名`。  
4. 查看/下载：校验选课关系后提供流下载或预签名 URL（按需）。

### 阶段 5：横切能力

1. **过滤器 → 安全框架**：未登录禁止访问业务接口；教师/学生接口分离。  
2. 统一异常与日志（关键操作打警告日志，对齐教程中「上传关闭项目」等审计）。  
3. 可选：对接原 `META-INF/context.xml` 仅当部署到外部 Tomcat 且使用 JNDI 时；Spring Boot 内嵌 Tomcat 通常直接用 JDBC URL。

### 阶段 6：测试与交付

1. 单元测试：DAO/Service；集成测试：Testcontainers MySQL（可选）。  
2. 接口测试：Postman/OpenAPI。  
3. 部署说明：Windows/Linux 路径、数据库账号、`report` 库初始化、存储目录权限。
